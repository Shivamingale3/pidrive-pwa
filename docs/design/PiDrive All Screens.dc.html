PiDrive — every screen, one page

Five modules, 50 screens, light and dark throughout. Everything below is the same source the individual files render — this page mounts them in build order so the whole design can be handed over in one go.

THE SYSTEM IN ELEVEN LINES
Architecture. A Raspberry Pi on the home network runs FastAPI over Postgres, with MinIO for media. The app is a thin client — every read and write is an HTTP call, nothing is cached on the phone.
Identity. The password is the account on the Pi. There is no sign-up; an admin creates users through the API.
The gate. Face ID unlocks the app, and the six-digit PIN is the fallback after three failures. The PIN also guards the private area on its own.
Lockouts. Five wrong passwords starts an escalating cooldown — 30 seconds, then 5 minutes, then an hour — with a live countdown that names the next wait.
Private area. Invisible outside its PIN gate, holding a folder tree of its own.
Saving. Passwords and notes autosave as you type. Notes take bold, lists and checkboxes.
Copying. Every copy action toasts, and the clipboard clears itself after 30 seconds.
Deleting. Permanent, behind a confirm. No trash, no undo.
Failures. Full screen when the app cannot go on, inline banner when one request failed, sheet when the user has to choose. Each one says what was written and offers one action.
Host. pi.local is baked in at build time and shown, not edited.
Type and colour. Plus Jakarta Sans throughout, monospace for labels and metadata. Warm neutrals — #101010 ink on #fbfaf8, #16181c surfaces in dark — with rust #c23c1a for failure and #0e7c66 for success. Inline styles only.
