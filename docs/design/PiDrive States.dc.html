PiDrive — failures and the missing pieces

Thirteen screens. Failures are sorted by severity: three take the whole screen because the app cannot go on, five sit inline next to the thing that failed, one is a choice sheet. Then Face ID with a PIN fallback, sort and filter as a pinned segmented control, and the media grid or list toggle. The last two are live — click the tabs and the view buttons. Dark row below.

SEVERITY RULE
Whole screen when the app cannot go on
Inline banner when one request failed
Sheet when the user has to choose
Every failure says what was written
Every failure offers one clear action
No screen claims a local copy exists, because none does. A failed read shows a skeleton and a retry, never stale data. Delete stays permanent behind a confirm, as agreed.
Face ID is the way in. The PIN shows up only after Face ID fails three times, and still gates the private area on its own.
